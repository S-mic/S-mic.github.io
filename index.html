An approval queue for speeding warnings

LOKi · fleet & HR
Problem
Tracker data is noisy, and a wrong warning to a driver is an HR problem.
What I built
A review queue where every case carries its evidence: GPS track, posted limit, peak reading. A person confirms each message from a "waiting to be sent" list. Repeat cases escalate to HR. Unclear cases, such as on-ramps or a limit taken from Google Maps, are held for a person.

After an HR and privacy review I turned trip recording off, added consent before any WhatsApp notice, and wrote down what was cut and why.

A repeatable AI workflow

AI agents run our software releases by following a written "skill": the steps, the checks, and the mistakes not to repeat.

  1. Delegate with context. The agent gets the skill: what to build, where it goes, and what "done" means.
  2. Don't trust the report. One of my releases reported success but had published a three-day-old image under the new version. The label was right and the contents were wrong.
  3. Check the content, not the label. The skill now compares the new image with the previous one and searches it for a string only the new change contains. It also confirms the release reached the shared repository, not just my laptop.
  4. Improve the method. 20+ changes to the skill so far. One removed a double build and cut frontend releases from about 29 to about 15 minutes.
  5. Hand it on. Anyone on the team, person or agent, can run a release the same way, because the context lives in the skill instead of in my head.

How I work

I map the process first: who's involved, what comes in, what goes out, the handoffs, the risks and the decisions. Then I build the lightest thing that fixes it and test the exceptions, not just the happy path. Rules handle what must happen every time, AI handles the fuzzy steps, and people make the judgement calls. I write it down so the next person, or the next agent, can run it without me.
